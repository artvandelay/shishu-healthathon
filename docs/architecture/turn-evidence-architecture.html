Core rule: “Not an answer to the active question” is not one thing. It may be another form answer, a clinical aside, unusable input, or unrelated speech. The policy must not force all four into one form slot.

2. Who decides the three practical lanes?

The lanes are policy outcomes, not a single opaque three-class classifier.

A. Local/server checks

  • No speech or empty transcript
  • Obvious audio/transport failure
  • Stale step or duplicate turn ID

Why “noise” stays deliberately small

A phone microphone cannot reliably identify TV speech versus a nearby caregiver from acoustics alone. The system only needs enough detection to avoid a form write. It retains minimal audit evidence, retries once, and does not build a rich taxonomy of noise.

Valid clinical speech that does not answer the active criterion is not noise. Example: “The child had fever after BCG” is a clinical aside unless it also answers the exact red-flag criterion.

3. Detailed turn lifecycle

Each branch names the owner and the state mutation allowed at that point.

Ingress — browser + Live session

  • Browser provides mic audio and quick replies.
  • LiveCallSession banks PCM and snapshots the current step.
  • Gemini Live supplies endpointing, input transcription and rendered speech today.
  • Epoch/step checks reject stale taps.

Evidence creation — new seam

  • Allocate one call-local sequence and immutable evidence ID.
  • Record source: voice, text, tap or late STT.
  • Bind to the pre-turn step token, never the cursor after mutation.
  • Reference audio by range/hash; do not duplicate PCM in SQLite.

Semantic reader — proposed

  • Act: answer, clarify, retract, stop, noise/unknown.
  • Relation: active, other form question, clinical aside, unrelated.
  • Claims have explicit targets when known.
  • Low confidence stays unresolved; it is not promoted to clinical truth.

Pure policy — proposed

  • Consumes interpretation, current state and pack rules.
  • Produces claim dispositions and at most one cursor action.
  • Cannot invent a target question.
  • Can retain evidence without changing the form.

Form reducer — keep

  • Current five-phase deterministic reduction remains.
  • CallState.answers remains the fast form projection.
  • Existing skip, follow-up and patient-safe behavior remains protected.
  • A temporary adapter maps accepted policy decisions to TurnCommand.

TurnController — later

  • Server owns finalization by turn ID.
  • Gemini tool calls become advisory transport signals.
  • Exactly one commit and cursor transition per turn.
  • Current cue recovery remains until replay evidence supports removal.

Decision API failure policy
  • Retry only timeout, connection failure, HTTP 408/429 or 5xx.
  • Safety block, invalid reply, empty answers and other 4xx do not repeat the same API call.
  • A slim second request uses only the remaining part of the 18-second budget.
  • Observed 0.8–1.0 second calls are historical examples, not a guaranteed bound; 5–7 second delays can come from model queueing or turn/tool protocol.
Call-level timers, separate from semantic classification
  • Soft call limit: 1,140 seconds.
  • Hard call limit: 1,200 seconds.
  • Maximum Gemini Live reconnect attempts: 5.
  • Playback tail that may still accept caller speech: 350 ms.
  • Captured PCM limit per turn: 960,000 bytes.

5. Proposed data contract

These structures are design candidates. Names and fields must be frozen in a separate architecture checkpoint before implementation.

TurnEvidence — immutable input
{
  evidence_id: UUID
  call_id: int
  sequence: int
  source: voice | text | tap | late_stt
  snapshot_step: str
  transcript: str
  selected_value: any?
  audio_ref: {path, start_ms, end_ms, hash}?
  received_at: timestamp
}
TurnInterpretation — model reading
{
  interpretation_id: UUID
  evidence_ids: UUID[]
  schema_version: str
  act: answer | clarify | retract | stop | unknown
  active_relation:
    active | other_form | clinical_aside | unrelated
  claims: ClinicalClaim[]
  confidence: number?
  model_metadata: object
}
ClinicalClaim — bounded assertion
{
  claim_id: UUID
  evidence_id: UUID
  target_qid: str?
  subject_ids: str[]
  status_or_value: any
  quoted_span: str
  relation: enum
}
PolicyDecision — deterministic result
{
  claim_id: UUID?
  disposition:
    accept_form | retain_observation |
    clarify | ignore | conflict
  reason: str
  form_write: TurnCommand?
  cursor_action: stay | advance | close
}
CallState — current form projection
{
  phase
  close_reason
  profile
  roster
  semantic_flags
  cursor
  last_answered_qid
  emergency_note
  answers: dict[qid, AnswerRecord]
}
TurnCommit — atomic persistence envelope
{
  evidence: TurnEvidence[]
  interpretation: TurnInterpretation?
  decisions: PolicyDecision[]
  next_state: CallState
  expected_prior_step: str
}
Compatibility boundary: do not add these records inside cursor_json. Legacy call state is strictly validated and currently falls back to a blank state on validation failure. Use separate append-only tables and one transaction.

8. Bounded delivery stages

FIRST

Lossless evidence seam

Capture immutable voice/tap/late-STT evidence and commit it atomically with unchanged form behavior.

Proof: no evidence loss, no cursor/report regression, no partial write.

SECOND

One semantic vertical

Active answer, another form answer, clinical aside, unrelated input, clarification and retraction.

Proof: pure deterministic policy against frozen real-call interpretations.

THIRD

Source conflict

Bundle same-step tap and voice evidence; contradictory sources trigger confirmation.

Proof: tap-yes/spoken-no cannot silently advance.

LATER

Server-owned progression

Finalize and commit by turn ID; Gemini Live remains audio/transcription/rendering transport.

Proof: duplicate, missed-tool, interruption and reconnect replays commit once.

Stage-one honesty: the evidence seam improves auditability and prevents future semantic loss, but does not itself prove that the model can distinguish TV speech from clinical asides. That requires a labeled replay evaluation in stage two.

9. Verification and evidence required before rollout

RED-first contract tests

Each new behavior must fail against current code before implementation. Record the actual failing assertion.

Frozen incident corpus

Label Calls #21–#65 by transport, semantic relation, conversational act, source conflict or UX/prompt failure.

Shadow reader

Run the structured reader without changing live form state. Compare its claims and relation against human labels.

Policy invariants

No write without explicit target; related/unrelated input cannot resolve active question; one cursor transition maximum.

Rollback boundary

Keep the legacy command adapter and feature flag until replay parity is achieved for the migrated question family.

Claims not yet proven
  • That one structured reader will outperform all current heads on every question family.
  • That TV speech is reliably detectable from mixed phone audio.
  • That clinician observations should appear immediately without confirmation.
  • That server-owned endpointing will reduce latency without harming barge-in behavior.
  • That the proposed table split is the final schema; it is a reviewable starting contract.

10. Decisions to make before code

Observation visibility

Recommendation: related but unconfirmed clinical asides remain audit-only first; expose them to the clinician only after policy and replay validation.

Conflicting sources

Recommendation: preserve both, keep the question unresolved and ask one confirmation. Do not make voice or tap universally dominant.

Unusable input

Recommendation: one retry, then leave unanswered or move by explicit pack policy. Never loop indefinitely.

First implementation boundary

Recommendation: ship the evidence ledger with unchanged user-visible behavior before changing inference or reports.
