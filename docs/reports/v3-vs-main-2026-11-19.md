# SHISHU `v3` vs `main` — Architecture Review, Timeline, and Release Assessment

**Date:** 2026-11-19 · **Branch under review:** `v3` @ `3069305` · **Baseline:** `main` @ `afd6c1f` (production)
**Evidence:** the full 79-commit diff, the test suite executed live during this review, both `docs/` design documents, `jd-raw-words.md`, 79 recorded agent transcripts, the UX benchmark artifacts, and both live Railway environments. Two claims below (schema collision, profile-step loop, `danger_now` fail-open, rule-op typos) were **reproduced by running code**, not inferred.

## 0. Read this first

### 0.1 `v3` is already deployed — to staging, at HEAD

```
$ curl https://shishu-staging.up.railway.app/health
{"status":"ok","build":"staging@3069305"}     # == v3 HEAD
$ curl https://shishu-production.up.railway.app/health
{"status":"ok"}                                # no build stamp = main
```

The question is therefore not "should we deploy `v3`" but **"should `v3` replace `main`, and what blocks that."** Four things block it.

### 0.2 Blocker 1 (hard): `v3` cannot boot against production's database

Production's `/data/intake.db` carries `main`'s schema. `v3` adds 13 columns to the same `calls` table and then, at *import time*, creates a unique index on one of them. `CREATE TABLE IF NOT EXISTS` is a no-op on an existing table, so every new column is silently absent and the index statement throws.

Reproduced against a `main`-shaped database:

```
main-shaped DB ready
IMPORT CRASHED: OperationalError no such column: share_token
```

The offending line is `intake/db.py:39-41`. `main` had an `ALTER TABLE ... ADD COLUMN` reconciler (`code/shishu-v2/db.py:110-113`); `v3` dropped it and has no migration path at all.

| `main` has (absent in v3) | `v3` needs (absent in main) |
|---|---|
| `engine, mother_name, child_name, child_age, child_gender, findings_json, summary_mother` | `pack_id, patient_name, roster_summary, caller_name, user_role, model_used, voice_used, telemetry_json, events_json, cursor_json, share_token, clinic_code, summary_patient` |

Survivable with a fresh `DATA_DIR` — but it must be a decision, not an accident. The failure mode if someone flips the branch is an app that will not start against a real clinic database.

### 0.3 Blocker 2: the HTTP surface is a breaking rename, plus one dropped capability

| `main` | `v3` | Consequence |
|---|---|---|
| `WS /ws/gemini` | `WS /ws/live` | any open tab or client on the old path dies |
| `/api/calls/{id}/mother.pdf` | `/api/calls/{id}/patient.pdf` | renamed concept (the pack may now be an adult OPD patient) |
| `/api/config`, `/api/settings`, `POST /api/settings` | **removed** | runtime tuning of live model, voice, VAD silence and watchdog timeout is gone from the admin UI |
| — | `/api/pack`, `/api/pack-asset/{k}`, `/api/calls/by-token/{t}/events` | new |

The settings panel is a genuine **capability regression** (`grep -c settings intake/static/admin.js` → `0`; on `main` it was a whole tab). Defensible — configuration now lives in version-controlled `pack.yaml` — but somebody who was using it at 2 a.m. will not thank you for finding out by absence.

### 0.4 Blocker 3: latency regressed ~250 ms at the median

From the head-to-head benchmark that was actually run (`reports/ux-compare-2026-11-16/`, same persona family, same TTS path):

| | `main` (prod) | `v3` (780 s run) | Δ |
|---|---:|---:|---:|
| Turns | 56 | 63 | +7 |
| **Avg perceived latency** | **2328 ms** | **2687 ms** | **+359 ms (+15%)** |
| **Median** | **2430 ms** | **2677 ms** | **+247 ms** |
| p95 | 2945 ms | 2976 ms | +31 ms |
| Max | 3201 ms | 4711 ms | +1510 ms |
| Premature cutoffs | 0 | 0 | — |

p95 is flat, so the tail is fine; the **median** moved. That is the Decision API pass sitting in the per-turn path where `main` had one Gemini Live turn and no classifier in between. It is the deliberate price of the architecture. But note the wart in the same log: `ui.max_quick_reply_reveal_ms: 6778.5` — the yes/no pills took **6.8 seconds** to appear on the first closed question of that call, which is precisely the "she answers before she sees the buttons" hazard the reveal rule exists to prevent.

### 0.5 Blocker 4 (clinical safety): the caller's voice is *discarded*, not just muted, while SHISHU speaks

```295:299:intake/live.py
        if self._mic_muted(now):
            self.preroll.clear()  # she can tap over SHISHU but never talk over her: her own voice is not a caller turn
            self.listening_ring.clear()
            return True
```

`_mic_muted` returns `True` during `DECIDING` (up to 18 s), during `CLOSING`, while `bot_generating`, and for the first 5 s of `PROMPTING`. In all those windows the frame is dropped before it reaches the buffer that becomes the audit WAV. **If a mother says "बच्चे को साँस नहीं आ रही है" while SHISHU is finishing its sentence, that sentence exists nowhere** — not in the decision path, not in the WAV, not in the transcript. The half-duplex decision was correct for echo (it removed 24–26 self-interruptions per call) but it was implemented as *discard* where *record-but-ignore* would have preserved the audit trail. This is the most serious finding in the review; see §6.6 for the fix.

### 0.6 Verdict

`v3` is a **substantially better architecture** and is **not a safe drop-in**. Plan a cutover with a fresh data volume, aliased endpoints, and a fix for §0.5. Do not flip the branch.

### 1.2 The architecture in one paragraph

A caller speaks. `live.py` owns a **turn-epoch state machine** (`PROMPTING → LISTENING → DECIDING → CLOSING`) with a monotonic `epoch` stamped on every wire message, so a stale packet cannot move the cursor. Each spoken turn becomes immutable **`TurnEvidence`** (source, transcript, snapshot step, the 16 kHz WAV) and goes to `gemini-decision-1` in **one multimodal pass** returning up to ~63 parallel structured heads. Those heads become a **`TurnInterpretation`**: a set of `ClinicalClaim`s, each with `target_qid`, `relation` (ACTIVE / OTHER_FORM / CLINICAL_ASIDE / UNRELATED), `domain_fit` (IN_DOMAIN / UNLISTED / NONE), `status`, `value`. A **pure** `policy.py` assigns each claim a `Disposition`. Only then does the **pure** `engine.reduce_turn` move the cursor, in five phases with exactly one advance. Evidence, interpretation, claims and decisions commit in one `BEGIN IMMEDIATE` transaction, and only *after* that commit does state change and the bot speak. Reports are a pure projection with **zero post-call LLM calls**.

Evidence → interpretation → policy → projection, with the LLM confined to one layer. `main` had `gemini_live.py` (1,764 lines) driving the voice session, mutating state, *and* importing `mother_report.py`. This is the difference that matters.

### 1.3 The invariant that matters clinically

The final commit split response state six ways, and only one means "she said don't know":

```28:29:intake/models.py
AnswerStatus = _enum("AnswerStatus", "CONCERN CLEAR ANSWERED UNKNOWN UNANSWERED NOT_APPLICABLE")
AnswerStatus.is_resolved = property(lambda s: s in (s.CONCERN, s.CLEAR, s.ANSWERED, s.UNKNOWN, s.UNANSWERED))
```

`UNKNOWN` = *she said पता नहीं / not tested*. `UNANSWERED` = *the call never got a usable answer*. Both resolve, so neither loops; both print as distinct rows with a fixed bilingual glossary on the patient PDF and `### Response State Glossary` on the clinician note. `UNKNOWN` is now written **only** when she actually said it.

This is the most important behavioural delta from `main`. `main`'s report had an `unknown` bucket, but its *engine* had no equivalent state — the report was compensating for a model that could not distinguish the two. `v3` fixes it at the bottom of the stack, which is why the fix holds.

### 1.4 Regex is genuinely gone from the semantic path

Zero `re.search` / `re.match` / `re.sub` / `re.compile` in `intake/`. The only regex is a clinic-code slug validator (`intake/app.py:60`). Compare `main`, which decided whether a name was valid with a phrase list and a negation regex:

```258:270:main:code/shishu-v2/checklist.py
    r"\b(not provided|not given|not stated|not mentioned|unknown|unspecified|"
...
_BARE_NAME_PHRASES = {"मेरा नाम", "मेरा नाम है", "नाम", "जी मेरा नाम", "हाँ मेरा नाम", ...}
```

### 1.5 What `v3` is better at, structurally

- **Post-call cannot lie** — *with one caveat.* `reports.py` imports `asyncio, functools, os, sys, tempfile, threading`, `jinja2`, `weasyprint` — and no HTTP client. On `main`, `summarizer.py:592` called `gemini-3.8-flash` post-call and `:615` called `gpt-4o-mini`. A `v3` report cannot disagree with its own transcript because it cannot reach a model. **The caveat:** the output is a function of `CallState` *plus* the decision log — `list_retained_observations` (`db.py:170`) joins `turn_evidence` with `policy_decisions`, so a clinician-only observation is not reconstructible from `CallState` alone. And `build_info()` is stamped into the PDF footer, so identical state rendered on two deploys yields different bytes. The invariant is "no model call after hangup", which is exactly what matters; "pure function of `CallState`" is slightly stronger than the code.
- **A stale turn cannot advance the call.** `step_token` + `epoch` + atomic commit-before-speak.
- **Tap and speech cannot silently fight.** `arbitrate_tap_turn` rolls back a premature tap when contemporaneous speech contradicts it, preserves both evidence rows *and* a `SOURCE_CONFLICT` decision, and cues one confirmation. Emergency/stop speech always wins.
- **A skipped question is never reported as "no".** `NOT_APPLICABLE` is deliberately **not** `is_resolved`.
- **Two clinical domains on one engine.** `fever-opd-hi` (14 questions: 5 gate, 3 single_choice, 2 profile, 1 bridge, 1 score, 1 multi_choice, 1 open_capture) runs on the same reducer, policy and templates as `shishu-hi` (62 questions: 56 gate, 2 profile, 1 single_choice, 1 bridge, 1 routing_gate, 1 open_capture). That is the moldability claim demonstrated, not asserted.
- **Resume works.** `?resume=<share_token>` restores state from SQLite, appends stereo WAV segments, re-speaks the active question, and merges telemetry counters so latency averages survive reconnects.

## 3. Solid

1. **The layering.** Evidence → interpretation → policy → projection. `engine.py` and `policy.py` pure; reports pure; the LLM confined to `decisions.py` / `extractor.py`. A reviewer can hold the dataflow in their head — impossible with `main`.
2. **`reduce_turn`'s five-phase single-advance reducer** (`engine.py:415-465`). Pure, copy-on-write, returns `CursorStep | None` from `_reduce_active` and performs **zero** premature advances. Structurally prevents a profile patch from swallowing an answer, and prevents double advances.
3. **The atomic semantic ledger** (`db.py:151-161`, `turns.py`). Evidence, interpretation, claims and per-claim decisions written in one `BEGIN IMMEDIATE` transaction with the cursor. Every cursor move is auditable and replayable.
4. **The claim → policy → command split**, including `arbitrate_tap_turn` handling the tap/speech race explicitly instead of letting the last writer win.
5. **Verbatim vs patient-safe notes.** `NoteText.verbatim` vs `NoteText.patient_safe`, with conservative default redaction (`_redact_note` redacts on `jumped`, `stated`, or multi-topic). Words survive when the form cannot hold them, and never leak to the mother's page.
6. **Decision transport discipline** (`decisions.py:73-113`). Per-request budget, classified retries (retryable vs terminal), cheaper slim fallback body, no hedging. Every choice backed by a recorded incident.
7. **The startup pack validator** fails fast with the *whole* error list.
8. **The stable-id roster merge** (`engine.py:207-220`) and the resume-appending WAV recorder (`audio.py:88-111`).

## 4. OK, with debt

1. **`live.py` at 977 lines is the complexity sink.** Socket, epoch FSM, echo gate, adaptive noise floor, `listening_ring`, cue ownership, resume, telemetry, recovery — and >40 attributes set in one `self.__dict__.update`. It also reaches into `db._write`. The `TurnController` split was explicitly deferred as "high risk".
2. **Inverted layering.** `intake/reports.py:237,240` imports from `scripts/` for `ensure_seeded`/`write_sample_pdfs`. The engine must not depend on the harness.
3. **`models.py` uses `create_model` + monkey-patched properties** (`AnswerStatus.is_resolved`, `AnswerRecord.verbatim_text`, `QuestionSpec.is_routable`). Invisible to type checkers and IDEs.
4. **`step_token` is stringly-typed** and parsed downstream (`reports.py:157`). Step-kind strings (`"profile"`, `"main"`, `"which_item"`) are used as an enum across three modules.
5. **`policy` is evaluated twice per turn** — once inside `decisions.interpret_turn_decision`, once in `live.apply_policy` — with the first result demoted to diagnostics.
6. **Docs have drifted.** `docs/design/v3-design-and-thinking-vad.md` claims 193 tests (**actual 236** at review time; **286** as of Nov 2026), 2,507 Python LOC (**3,089**), `live.py` at 839 (**977**), `db.py` at 132 (**247**), and "16 required thresholds" (**21**). `docs/design/v3-moldability-boundary.md` repeats the 16/17 figure and says `profile_slots[].type` is not honoured — **it is** (`extractor.py:19, :50-60`). Prefer [`docs/spec/TECH-SPEC.md`](../spec/TECH-SPEC.md) for measured counts; design notes may lag.
7. **Declared-but-unwired config.** `version`, `domain`, `setting`, `patient_scope`, `ui.choice_buttons`, `timers.watchdog_timeout_sec`, plus report keys `nothing_reported_en`, `no_alerts_en`, `no_negatives_en`, `partial_call_en`, `universal_advice_title_hi`, `universal_advice_why_hi`. Changing them does nothing, silently.
8. **Hardcoded English clinician prose that assumes a mother.** `reports.py:119,143` emit `"Mother's words: …"` for **every** pack, including the fever OPD pack where the patient is an adult.
9. **`MAX_STEP_ATTEMPTS = 2` is not configurable** (`engine.py:10`) while nearly everything around it is declarative.
10. **The report projection data model is fixed** even though templates are not. A prescription, referral letter or scored risk card needs Python. Correctly documented as the boundary — and it is the boundary product growth hits first.
11. **Single-process only.** `_ACTIVE_CALLS`, `_PENDING_FINALIZE` and one global SQLite connection mean a second worker breaks resume.
12. **`db._read` and `_write` take the lock separately**, so concurrent `_emit` and `append_transcript` from the watchdog and pump tasks can lose updates; whole JSON blobs are rewritten per STT chunk (O(n²)).

## 4b. Excluded by design (not gaps — decisions)

Stated so a reviewer does not file these as bugs. Sourced from `docs/design/v3-moldability-boundary.md` §3 and verified against the code.

| Excluded | Why it is a decision, not a gap |
|---|---|
| Telephony / IVR / WhatsApp / messaging | Transport is browser WebSocket only. No `press 1` path — JD's explicit rejection of a "dumb IVR". |
| A second STT/TTS provider | Gemini Live is the voice stack, by choice. Nothing abstracts it. |
| Dates, numbers with units, computed values (BMI, gestational age, dose) | The answer vocabulary is fixed at eight question kinds. `profile_slots[].type` is honoured in the extractor but there is no unit/range validation. |
| Nested forms, loops, "repeat this block per child" | Exactly **one** ordered forward pass. `roster_scoped` attributes one concern to one child; it does not multiply the form. `MAX_STEP_ATTEMPTS = 2` and re-ask depth are code. |
| Adding or retyping a Decision head | The head inventory is fixed in `decisions.py`. A pack can rewrite every head's instructions and all 21 thresholds, and cannot add, remove, or change what a head's result *does*. |
| Layout / screen-flow changes, tablet kiosk, progress sidebar | `call.js`/`admin.js` are engine files. A pack changes their **words**, not their structure. |
| Prescriptions, referral letters, longitudinal charts, FHIR, scored risk cards | `project_summary` emits a fixed data model. Templates are fully rewriteable; the model they receive is not. |
| EHR integration, appointment booking, analytics, server-side send | Not modelled at all. |
| Share/email delivery | `navigator.share` with a download fallback. `call.html` has one `navigator.share` call vs `main`'s full share sheet with abort handling and a `share_clicked` event. |
| Runtime model/voice/VAD tuning from the admin UI | Deliberately replaced by version-controlled `pack.yaml`. See §0.3 — the cost is a lost operator capability. |
| A second concurrent worker | Single SQLite connection + in-process dicts. Scaling out breaks resume. |
| Multi-child clinical records beyond one flat roster | One roster, `item_N` ids, `age_years`/`tag`/`name`. No per-person sub-record, no second roster, no relationship graph. |

The honest framing: **configs make many versions of *this* intake; code makes a different intake.** The line is drawn at "one ordered pass over one patient or one flat list of people, answered by voice with optional tapping."

## 5. Fragile — ranked by consequence

### 5.1 🔴 Caller voice during bot speech is destroyed, not just ignored
§0.5. `live.py:295-299`. During `DECIDING` (up to 18 s), `CLOSING`, `bot_generating`, and the first 5 s of `PROMPTING`, the frame is dropped before it reaches the audit buffer. An emergency spoken over SHISHU is lost from the decision path **and** the WAV. This is a clinical-safety bug, not a UX one.

### 5.2 🔴 A profile step has no attempt cap — the call can never leave `intro_name`
Reproduced by driving the reducer:

```
start step: intro_name
turn 1..8: step_token='intro_name' attempts=0 qid=intro_name   (x8)
```

`attempts` never increments and `step_token` never changes. If the caller declines her name, or the extractor times out, the step re-asks indefinitely until the 30 s silence close or the 20 min hard limit. A caller who refuses to give a name — entirely reasonable — ends with an empty, unusable call.

### 5.3 🔴 `danger_now` fails open on a malformed Decision response
Reproduced against `interpret_turn_decision` with a real emergency utterance and `danger_now_min_yes = 0.494`:

```
head MISSING               -> emergency=False
noul = NaN string          -> emergency=False
noul = null                -> emergency=False
noul = 0.30 (below thr)    -> emergency=False
noul = 0.97 (clear emg)    -> emergency=True
```

A 200 response that omits the safety head, or carries a non-finite value, is read as **"no emergency"**. There is no per-head schema validation, and it matters that the test suite has **no tests at all** for `_verdict`'s `response_invalid` / `empty_answers` / 5xx / 4xx / `connection_error` branches (§6.2) — so this failure mode is both reachable and unguarded. For a safety head this must be fail-**closed**: a missing `danger_now` should force the retry/unknown path, never a confident "not an emergency".

### 5.4 🟠 Unknown rule operators silently change clinical logic
Reproduced:

```
valid  {'roster_op':'non_empty'}   -> True
typo   {'roster_op':'nonempty'}    -> False
unknown field op                   -> False
```

`engine.py:59` returns `False` for any operator not in `_OPS`, and `_roster_op` (`engine.py:37-43`) falls through to `none_match`-shaped semantics for anything unrecognised. The validator (`pack.py:37-47`) checks that rule *names* exist but never that a rule *body* uses a known operator. A typo in `skip_if` is safe (question gets asked); a typo in `implications[].when` or `variants[].when` — rules that must be **true** to fire — silently does nothing. Also: a malformed `heads.stated_template` raises `KeyError` on every turn, which becomes 3 strikes and a `TECHNICAL_FAILURE` at runtime instead of a load-time error.

### 5.5 🟠 Audio-forward failure tears down the session and bypasses resume
If forwarding audio to Gemini fails (during `_reconnect`, or after `go_away`), `on_audio` returns `False`, which kills `_browser_loop` and ends the whole session — the resume-handle path is never consulted, and `on_audio` ignores `reconnecting`. A blip that resume was built to survive instead ends the call. `_open_live` is always faked in tests, so a failed reconnect has never been exercised.

### 5.6 🟠 `_answer_tools` is awaited inline in the Gemini receive pump
For up to ~26 s, so `go_away`, resumption updates and interrupts queue behind the Decision call.

### 5.7 🟠 Decision API is a hard single point of failure, and 21 thresholds are overfit
One pass, `attempt_timeout_sec=12.0`, `total_budget_sec=18.0`, one sequential slim retry. Three consecutive failures close the call. The design is deliberate (Call #16 proved hedging was worse), but **`v3` cannot run a call at all without a healthy `gemini-decision-1`** — `main` could still complete a call with a broken summariser. New operational dependency; belongs on the runbook.

The calibration corpus is **50 cases, 40 dev / 10 holdout**. The holdout has **zero emergency cases, zero caller_stop cases, zero audio cases**, 16 of 50 cases are on one question (`birth_jaundice`), and `score()` returns `1.0` for an empty metric set — so a category with no cases scores perfect. The cached `intake/storage/calibration_raw_*.json` (Nov 19 01:03) predates the `decisions.yaml` edit (15:29) and may not match shipped thresholds. Thresholds are 4-decimal (0.494, 0.5739, 0.4914…) and drift silently when the model updates.

### 5.8 🟡 Python still re-arbitrates the model in ~100 lines
`interpret_turn_decision` (`decisions.py:279-376`) holds the suspect logic:

| Line | Behaviour | Judgment |
|---|---|---|
| `decisions.py:217-221` `_quiet_split` | adds clear+unknown probabilities so the pair can win | Python overrides the model's uncertainty |
| `decisions.py:222-231` `_clarify_split` | concern+clarify → clarify | patched for one event (Call #67 Event 24) |
| `decisions.py:325` | a gate CONCERN is vetoed if `active_topic` is false | one head overrules another |
| `engine.py:315-317` | named clarify counts only if exactly one stated head fired | ASR-garble patch for Calls #47/#57 |
| `engine.py:83` | a child with unknown sex renders with the male grammatical form | a gender assumption shown to the caller |
| `engine.py:19-22` | `merge_transcript_chunk` collapses a repeated word ("नहीं"+"नहीं") | protocol logic, but lossy |

This is the residual of the "Python blindfolding the models" pattern JD asked to eliminate. It is much reduced but not gone.

### 5.9 🟡 Test fidelity at the Gemini and Decision boundaries
See §6.

### 5.10 🟡 The nudge button
`styles.css:541` defines `.nudge-btn.hot`, but `call.js` **never adds `.hot`** — the button never indicates it is ready. Server-side `on_nudge` (`live.py:415-421`) re-speaks the question without evaluating the caller's pending speech, so tapping it during a slow turn can produce dead air. Diagnosed during Call #65; no fix landed.

### 5.11 🟡 Smaller but real
- Turns over 30 s keep only the **last** 30 s; the start of the speech is dropped (`live.py:314`).
- `_MAX_RECONNECTS = 5` is counted over the **whole call** and never reset.
- A resume can reopen a call already closed for silence/time-limit/technical-failure and **resets the time limit** (`live.py:908-920`).
- `get_call` writes a share token inside a getter (`db.py:235-238`).
- A production-logic test hook sits in `decisions.py:96` (`transport and api_key is None`).
- The 6.8 s quick-reply reveal (§0.4) has no ceiling.
- `ensure_seeded` runs `seed_replay.py`'s regex/keyword heuristics at **every production boot**.

## 6. Test suite

**236 tests, all pass, 9.9 s, fully offline, no API key.** Verified live during this review. Fast enough to run on every save, which is the property that matters.

### 6.1 What is genuinely good

`test_policy_invariants.py` is the strongest test in the repo: ~36 anchors × 8 patterns, six laws, a guard that the matrix cannot collapse (`assertGreaterEqual(seen, 250)`), and a RED run that found **23 real violations in 288 cases**. The laws are meaningful — no resolved answer without an accepted decision, no sentinel token in patient output, cursor consistency, tap rollback — not trivially satisfiable ones.

Also load-bearing: the single-owner prompt-cue tests (RED: cue spoken twice), drop-and-resume through real `handle_live_ws` + SQLite, self-interrupt recue with wire order, acoustic regimes (fan is not a caller), tap-conflict + emergency, Wave4 real measured probabilities (`0.8559` over a `0.80` gate revising CLEAR→CONCERN), and the atomic-rollback test that uses a **DB trigger to force a mid-write failure** and asserts no partial ledger rows survive. That last one is the best-designed test in the suite.

### 6.2 What is not proven

- **The Gemini fake never speaks Gemini's protocol.** `FakeSession.send_realtime_input(audio=...)` **ignores the audio**, so Gemini's AAD never reacts and no `input_transcription`, `interrupted` or `turn_complete` is ever generated from audio. Every turn boundary is hand-placed. Tests call `_hear(...)` and `_next_question()` directly, bypassing `on_message` and its parsing. `go_away`, `session_resumption_update`, `tool_call_cancellation`, `generation_complete`, and a `receive()` that raises are never produced. The fake does often send one field per `LiveServerMessage` where real Gemini bundles audio+transcription+turn_complete.
- `turn_with()` scripts the outcome head at 0.97 and rivals at 0.006 — every happy path sees a perfectly confident classifier. Contested confidence is never exercised end to end.
- **The Decision API failure branches are untested.** `_verdict`'s `response_invalid`, `empty_answers`, 5xx-retry, 4xx-terminal and `connection_error` paths have no tests. Wrong types, non-dict `answers`, missing heads, and probabilities not summing to 1 are untested — which is exactly the gap that makes §5.3 possible.
- **The Gemini recovery paths are untested.** `go_away`, `session_resumption_update`, the `_pump`/`_gemini_loop` failure path and `_open_live` are never exercised; the 90 s grace-expiry test asserts the call is *pending*, never that it finalizes. A drop while a decision is in flight is untested.
- **The fuzzers are hand-enumerated, not searching.** None of the three uses randomness or a property-based library. `test_policy_invariants.py` is ~36 anchors × 8 fixed patterns, and its interpretations come from the author's own `_interp` — so the interpreter→policy contract is never fuzzed, and no pattern sets `emergency`. The laws are real (they found 23 violations), but the space is not explored.
- **`test_semantic_policy.py:372` tests retraction on the wrong pre-state** — it applies the retraction to `st0` (state *before* the concern), so retraction of a held CONCERN is not what that case checks.
- **Red flags are never asserted from the seed scenarios** — the single most important missing assertion for a screening app. A red flag in `reports.py:~140-159` is simply every CONCERN on a routable, reportable question; the seed tests iterate `red_flags`/`no_flags`/`incomplete` only to check a **file was written**, and the red-flag *text* is asserted only for the emergency case. A reducer that silently stopped recording concerns would pass every PDF test. Compounding it: `scripts/seed_replay.py` builds those seed reports with a keyword heuristic ("नहीं"-prefixed answer → CLEAR), so the fixtures are neither a recording nor the real classifier.
- **No real recorded audio is replayed in `tests/`.** The only real WAVs are 4 files used by a network-bound calibration script. No Gemini wire capture exists in the repo.
- Gaps with no behavioural test: language switch / Hinglish, twins with **identical names**, "दोनों" resolved end to end, a plain emergency *during bot speech*, silence during `DECIDING`, report text for `SILENCE`/`TIME_LIMIT`/`TECHNICAL_FAILURE`, 90 s grace expiry, `_open_live` failure, and a Gemini drop while a decision is in flight.
- **`3069305` (HEAD) added ~350 lines of tests with no RED record** in the commit body, against the project's own rule. 12 of 49 `tests/`-touching commits do record RED assertions; HEAD is not among them.

### 6.3 Noise

Tests that can only fail when a human edits a constant or string, or that echo their own fixture: constant pins (`4096`, `2048`, `1600`, `200`), the meta-row test asserting `decision_ms == 200` (the fixture's own hardcoded value), enum-value pins, `hasattr` negatives, YAML substring pins, prompt-text-contains-words, health `build` compared against `build_info()` from the same function, and a PDF-filename test where the mock returns the header the test then asserts.

## 7. Release assessment

### Is `v3` better than `main`?

**Architecture: yes, decisively.** Layering, post-call purity, the six-state response model, absence of regex, the atomic ledger, tap/speech arbitration, and two clinical domains on one engine are all verified and all better. `main` could not be made to do this without the same rewrite.

**Deployable today: no.** A schema collision that prevents boot, a breaking HTTP surface with a dropped capability, an unowned latency regression, a clinical-safety audio-drop bug, and an open correctness concern from JD himself.

### Release note (draft)

> **SHISHU v3 — Moldable Voice Patient Intake**
>
> `v3` replaces the single-purpose `shishu-v2` app with a voice-intake **engine**. Every question, Hindi string and report template now lives in a declarative pack under `packs/`, so a new intake is YAML, not a fork. Two packs ship: the existing mother-and-children screening call (62 questions, multi-child roster) and a new OPD fever triage (14 questions). Runtime Python is down 69% (9,973 → 3,089 lines); the suite is up to 236 offline tests running in 9.9 s.
>
> **Behaviour that changes clinically**
> - **Response states are distinct and printed.** `UNKNOWN` ("she said don't know") is no longer conflated with `UNANSWERED` ("the call never got an answer"). Both appear as separate rows on the patient PDF with a fixed Hindi glossary, and as `### Response State Glossary` on the clinician note. Nothing prints "नहीं" because an answer was missing.
> - **Reports are deterministic.** Both artifacts are pure functions of stored call state — **zero post-call LLM calls** — so a report cannot disagree with its own transcript.
> - **Answers are attributed, not guessed.** Each turn produces immutable evidence, a structured interpretation, and a policy decision, committed atomically before the bot speaks. A stale packet cannot advance the call.
> - **Tap and speech can no longer fight.** A contradicting tap is rolled back, both signals preserved, one confirmation spoken. Emergency and caller-stop speech always win.
> - **Half-duplex by design.** She can tap over SHISHU, not talk over her. This removed an entire class of interruption bugs and is a deliberate requirement change.
>
> **Operational changes**
> - `gemini-decision-1` is now in the per-turn path. **No healthy endpoint, no call.**
> - Four new tables plus a reworked `calls` table. **Requires a fresh data volume or a migration.**
> - `WS /ws/gemini` → `/ws/live`; `/mother.pdf` → `/patient.pdf`; new `/api/pack`, `/api/pack-asset/*`. Runtime `/api/settings` is removed — model, voice and VAD are pack config.
> - Median perceived turn latency is ~250 ms higher (2.68 s vs 2.43 s) — the cost of the classifier.
>
> **Known open:** backtracking is improved but unverified by a human call since the fix; twins untested since the evidence redesign; the calibration corpus is 50 cases (40/10) with no emergency or audio cases in the holdout; the caller's voice during bot speech is muted and currently not recorded.
