## What is not a storage bug

Calls 151, 153, 154, and 158: Gemini spoke as if it had noted the fact and never called `record_answers` for that topic. Call 151 (mama, BP), call 153 (miscarriage), call 154 (पहले वाला operation), call 158 (the test was normal). No tool error. Nothing to store.

Call 152: the neighbor's fits were not stored as the child's problem. The topic stayed `not_asked`. The model did not record a denial either.

Call 155: the children sentence was never a tool call. Events show name, marriage, then `topic.body_fits_milestones` with `value` the string `"true"`, `scope` `specific`, `child_ids` `["child_1"]`. There was no child slot, so the existing gate skipped the topic and the batch raised `no applicable update`. That rejection is the rule already in the contract. The string `"true"` was not stored.

Call 149 kept the later birth value `operation` and filled `delivery_type`. Call 156 closed on emergency with the child and the birth saved. Call 157 kept unmarried, a past pregnancy, and `fam_related` `not_applicable`.

## The mode

**A count written on the next turn drops the ages she already said.**

Call 150. She said `एक बच्चा है, तीन साल का।` The events for that turn have no tool call. The next user line was `ठीक है।` That turn called `record_answers`. The saved state is one child with `age` null, and `intro_children` is still `not_asked`. There is no children history row, which is the bare-count path: the current utterance had no ages, so the server opened a slot and stored nothing in it.

The same words in the current utterance already fill a count. The ages were one line earlier, and the server did not look there.

## The contract

A bare count, or a child list whose ages are all empty, uses the ages she already said. The current line wins when it has ages. When it does not, the nearest earlier line that states exactly that many ages fills the slots. A nearer line that states a different number is not skipped, and it is not used. `intro_children` is answered once those ages are stored.

`gemini_live.py` keeps each user line and passes the earlier lines into `apply_updates`.
