# Wave 1: 50 live scenarios

Date: 2026-11-08
Server: the call-44 fix (`9b333fe`), port 8023
Calls: 45–94
Raw log: `reports/call-state/wave1-raw.jsonl`

Each scenario was 5–8 text replies, except the two caller-stop checks (w1-11 stops on the name question, w1-44 stops on the marriage question). The last line was `नहीं, कॉल एंड करिए प्लीज।` or a clear emergency line. A reply was sent only after a telemetry `turn_complete` that followed assistant audio or a transcript.

## Result

33 of 50 calls failed a structural check. 17 did not. **No topic was wrongly `not_applicable`.** The calls 38–43 wipe, where a bare count became an empty list and 28 child topics were marked `no_children`, did not recur.

The failure moved. A count is no longer stored as "no children". It is also not stored as a child list. The server stays on `intro_children`, Gemini has already moved on, and the clinical tool call comes back `no applicable update`.

## What the clean calls actually reached

A clean check means the marital value, the child count, the close reason, and the tool log matched. It does not mean the scenario's clinical point was stored.

Reached and stored:

- No children, married, never pregnant: call 45. Ever-pregnant-no skipped the pregnancy block. The server still asked thalassemia. That matches the current rule.
- Unmarried, no children, one past pregnancy: call 50. `fam_related` is `not_applicable`.
- About to marry, never pregnant: call 51.
- Pregnant now, no living child, `has_delivered` false: call 76.
- Thalassemia "no" with no children: call 85, topic stored, still on `profile.ever_pregnant`.
- About to marry, one child age 2, birth mode answered: call 77. Stopped on `birth_term`.
- One child saved, and a later topic stored while the server was still on birth: hearing call 71 (`birth_hearing_vision` true for "the test was normal"), fasting call 74 (`ill_fasting` true). True is a positive value in `_is_positive`, so call 71's "normal" is stored as a yes.
- Preterm 7.5 months and NICU yes, one child: call 92. Both topics stored while the server was still on `birth_mode`.
- Caller stop on the first question: call 55, still on `intro_name`. Caller stop on the marriage question: call 88. Name was saved, marriage was not.

Clean, and the point of the scenario was not reached:

- Maternal uncle's BP, call 58. One child saved. `fam_bp_stroke` still `not_asked`. Stopped on birth.
- Neighbor's fits, call 59. Same. The neighbor fact was not stored.
- "पता नहीं" / "अगला सवाल", call 65. The child was saved. The call ended on the bridge, before those words were an answer to a clinical question.
- Ram and the knee, call 82. Two children saved. `body_joint_swelling` still `not_asked`.
- Operation, reason unknown, call 91. Child age 3 saved. `birth_mode` still `not_asked`. No tool error. Gemini did not record the operation.

Emergency close itself worked on calls 54 and 87 (`close_reason` emergency). Both were still on `intro_children`, so the child was not saved. An emergency after a saved child was not reached.
